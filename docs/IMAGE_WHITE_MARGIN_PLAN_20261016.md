# 2026-10-16 大白边图片处理方案

用户本轮要求提出方案，本文件记录建议；本轮没有批量裁图或改动原始媒体。

建议采用“自动找边界、逐图复核、统一显示窗口”的方式。网页显示紧凑版本，点击仍看完整原图。裁切范围只针对主体外的空白，不去除图内白色区域，也不拆散科研合图。

## 先区分空白来源

| 情况 | 处理建议 |
| --- | --- |
| PNG／JPEG 文件本身有大面积外白边 | 记录每张图的主体边界，用 CSS 或 SVG 窗口显示该区域；原文件与原图链接保留 |
| `object-fit: contain` 配合固定高度／比例撑出空白 | 调整对应图框的高度、比例或内边距；不把图表强行改成 `cover` |
| 设备透明图的透明画布较大 | 独立设备插图可以单独设窗口；Homepage 分层插画、动画人物不能自动裁，画布承担场景定位 |
| Model 分图、Contribution 卡牌、Safety 设备分图已有窗口 | 先检查当前实际显示，不能再次按整张原文件盲裁 |

## 建议实施方式

1. 以页面、图号和原图路径建立清单，合并重复引用；记录原尺寸、原件 SHA-256、现有显示窗口及候选四边坐标。对 CSS／脚本插入的图片也按实际页面补齐。
2. 自动检测仅生成建议边界，不能直接批量发布。用原分辨率复核最外侧文字、坐标轴、误差线、比例尺、A–F 编号和箭头；在检测到的内容外再留约短边 1–2% 的安全边距。阈值不稳定、浅灰图线或零散标记由人工定边。
3. 用共用显示窗口接入逐图参数，图片比例保持，原图入口不变。各页面继续遵守现有设备图、科研图和 Model 图框大小要求；同图多处引用核对一致，Homepage 分层场景与既有裁切不套批量规则。
4. 按页看裁前／裁后并排预览，再检查桌面和手机：文字完整、合图完整、无拉伸、无新溢出，原图仍可打开。保留参数清单，可逐图撤销。

建议先用上述三类明显图片（Measurement 曲线、Result 合图、Contribution 流程图）试排；确认视觉标准后，再把同一标准用于其余候选。本轮只提交方案，不改变这些图片的展示。
