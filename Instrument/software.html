JLU-SPH · Android interface

Device Control, Fluorescence Acquisition, and Result Interpretation in One Interface

Our Android app is the mobile interface for the multichannel detector. Connect to the AI Box over Wi-Fi, set the heating time and temperature-control switches, and view temperature, fluorescence curves, returned images, and tube labels in one interface.

01

Overview

We developed an Android app that lets users operate the detector from a phone. It sends control commands over TCP and receives temperature readings, fluorescence data, images, and tube labels from the AI Box. Image processing runs on the AI Box; the app handles interaction, communication, and display.

Six core functions

01

Connect the device

Enter the AI Box IP address and port, establish the TCP connection, and reconnect when needed.

02

Configure a run

Set heating time and temperature controls. The second generation adds separate control switches and servo commands.

03

Monitor the reaction

Follow the heating countdown and temperature returned by the device.

04

Visualize fluorescence

Display the two received curve values as TUBE1 and TUBE2 over time.

05

Receive analysis results

Request an image and display the tube labels returned by device-side analysis.

06

View and save images

Inspect the acquired image in the app and retain it through the image-viewing and saving functions.

One data flow

  1. 1Connect over Wi-Fi
  2. 2Send parameters
  3. 3AI Box acquires and analyzes
  4. 4Return temperature, curves, images and labels
  5. 5App displays results

Five tube-result labels and two fluorescence curves describe different outputs. The second-generation protocol supplies only data1 and data2 for plotting.

Developing alongside the detector

The mobile interface began with device connection and expanded to support control, reaction monitoring, acquisition, and result viewing.

  1. Stage 1

    Establishing the connection

    Need: a direct mobile interface for connecting to the instrument. Added: the app interface and device communication for sending basic commands.

  2. Stage 2

    Displaying the reaction

    Need: visibility into temperature, elapsed time, and fluorescence. Added: heating countdown, temperature display, and live curves; separate control switches in the second generation.

  3. Stage 3

    Presenting the results

    Need: viewing the acquired image alongside device-side analysis. Added: two-tube results in the first generation, then five color-coded labels and servo control in the second.

02

Architecture

The Android app is a Java TCP client on a local Wi-Fi network. NetworkService parses incoming messages; MainActivity manages interaction and display. MPAndroidChart plots received values. The AI Box integrates thermal, optical, mechanical, and image-analysis functions.

Message framing

Every message starts with an eight-byte header: two big-endian 32-bit integers specify the payload length and the frame type, followed by the payload. Frame type 0 carries text; type 1 carries image content. JSON control commands use UTF-8. A plain JSON line without this header is not a valid frame.

4 bytesPayload length4 bytesFrame typeN bytesPayload

Control commands

CommandGenerationPurpose
get_imageBothRequest an image and result update.
get_temBothRequest temperature separately.
set_temBothSend a numeric temperature-control value.
set_tem43
set_tem90		SecondSend 1 or 0 from the two temperature-control switches.
set_servoSecondSend a numeric servo-control value.

Text responses contain type, string-valued content, and an optional timestamp. The second-generation tubeluminance message contains data1 and data2; the app records reception time for each plotted point. Temperature arrives independently as tem.

Read a protocol example

This illustrates a message payload, not an experimental measurement. It must be sent with the binary frame header.

{"type":"tem","content":"25.0"}

For image envelopes, Base64 handling, and case-sensitive fields, read the complete protocol.

Device-side analysis, client-side labels

The second-generation app maps server codes 0, 1, 2, and 3 to tube_green, tube_red, tube_blue, and tube_null. The biological meaning follows the assay and server implementation. The Android repository does not contain the device server, firmware, inference model, model weights, or experimental dataset.

04

Reusability

Connection, parameter configuration, monitoring, and result viewing share one mobile interface. Other teams can adapt the communication parser, MPAndroidChart plotting, and result display to their own device commands and field mappings.

Reuse the client

Start from either Java source project. Keep communication and display responsibilities separate when adapting NetworkService and MainActivity.

Match the device

Implement the TCP frame and the selected generation’s commands on a compatible server. Hardware command values must agree with the firmware.

Verify the adaptation

Check connection, separate temperature updates, two-series plotting, image handling, and the tube-label mapping against your device and assay.

Build from source
  1. Open one generation directory as a separate Android Studio project.
  2. Select JDK 17 as the Gradle JDK and install Android SDK Platform 34.
  3. Synchronize Gradle, then select the app configuration and run on Android 7.0 / API 24 or later.

The projects use Gradle 8.2 and Android Gradle Plugin 8.2.0. From the selected project directory in PowerShell:

.\gradlew.bat assembleDebug

The corresponding server and model require separate configuration. Read the full build and verification notes.

Repository verification covered source-file integrity and documentation consistency. Compilation and device tests were not completed during source publication. The supplied tests are template checks; the second-generation instrumentation test still expects the first-generation application ID.

Quick start

  1. Install. Download the matching APK for Android 7.0 / API 24 or later. Both supplied app generations declare version 1.0.
  2. Connect. Start the compatible AI Box server, join its network, and enter the actual IP address and port. The recorded setup uses 10.42.0.1:8080.
  3. Configure and monitor. Set heating time and the controls supported by the device and assay. Confirm returned status and temperature; inspect TUBE1 and TUBE2 in the data view.
  4. Request and inspect. Request an image, inspect the returned tube labels, and use image viewing or saving as needed. Interpret labels according to the assay.
If the connection or data does not update

Check that the device server is running, the phone can reach its network, and the IP address and port match the device. Reconnect and request an update. Empty or unchanged plots alone do not establish a negative assay result. Record the app generation, Android version, and observed status when reporting an issue.
